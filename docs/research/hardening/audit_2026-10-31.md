### C1. One concept ("a head / a target / a loss weight") is defined in 4 vocabularies, so every addition is an N-file edit

**Flaw.** There is no single declarative object that says "this model output is head H of target T, with label L, loss kind K,
weight W, evaluation role R"; each layer re-derives it from string conventions (`y_{t}_class_logits`, `{t}_reg`, `{t}_class`).

**Evidence (loss weights, the owner's example).**
- Four independent weight mechanisms, none owning the others: a static per-target `loss_weight` read with a silent `1.0`
  default (`trainer/trainer.py:44-46`); `CONFIG['target_loss_weights']` (`data/defaults.py:101`) which no trainer code reads
  (only printed at `data/runtime.py:170`; its helper `head_loss_weights`, `data/heads.py:211`, has **zero callers**);
  Kendall `UncertaintyWeightedLoss`, applied by task type via an exclude list (`trainer/trainer.py:58-61`, default excludes
  `evidential`, so two groups of heads are balanced by two different rules); `TaskWeightUpdater` mutating the weight
  variables from a callback (`trainer/metrics.py:29`, enabled by `task_weight_update_frequency`, "only when Kendall is off" is
  a comment, enforced at `trainer/system.py:262-263` by silently not adding the callback). Sub-term weights are a fifth
  mechanism (`lambda_reg`, `lambda_calib` schedules, `trainer/tasks.py:206-209,238-241`).
- A run cannot set a loss weight through `RunSettings`: `TrainSettings` has no such field (`workflow/settings.py:180-228`). The
  only route is the free-form `anti_memorization_trainer` dict, which is merged **only if** `anti_memorization` is on
  (`workflow/run.py:329`, `... if _am else {}`), so the same override is silently dropped on the old architecture.
- The selection metric depends on the objective: the default monitor is `val_raw_loss` (`workflow/settings.py:199`), which is
  the weighted sum of task losses plus scheduled penalty terms (`trainer/trainer.py:153`, `trainer/tasks.py:209`). Changing a
  weight or a lambda changes which epoch is "best", so runs are not comparable (see also C7).
- Head vocabulary in four places that are never cross-checked: pipeline `enabled_heads` `{high_class: bool, ...}`
  (`data/defaults.py:90`, `data/heads.py:56-69`); model `head_types` `{high: [nig_regression, binary_classification]}`
  (`model/config.py:39`, rebuilt by hand at `workflow/run.py:277-280`); trainer `targets` `{high_reg, high_class}` built by hand
  in `workflow/training_config.py:6-37`; evaluation `TargetSpec` with magic column indices (`evaluation/targets.py:144-146`,
  `future_col=6/5/4`, `price_index=0/1/2`, which duplicate `core/schema.LAST_COLUMN_INDEX`).
  `data/heads.py` claims "every stage calls `get_target_heads`" (docstring); in fact `validate_head_config`,
  `get_output_names` and `head_loss_weights` are called by no module outside `data/`. Turning off `enabled_heads['high_class']`
  removes the label (`data/windows.py:233`) while model and trainer still expect it.
- Output-name literals are parsed and rebuilt in 31 files: `y_{t}_class_logits` appears in `model/diagnostics.py:83,291,444`,
  `model/layer_report.py:65,175`, `workflow/capacity.py:169`, `workflow/selective_eval.py:~57`, `tools/bracket_eval.py:68`,
  `evaluation/targets.py`, `workflow/{candle_baseline,chicks_bridge,generalization,permutation_control,reports,wiring_selftest}.py`.
  Target recovery by string slicing `k[2:-len("_class_logits")]` (`model/diagnostics.py:84`, `model/layer_report.py:66`).
  The key named `...class_logits` carries a **probability** (sigmoid; `model/heads.py:63-68`) fed to `from_logits=False` BCE.
- The literal tuple `('high','low','close')` is repeated at ~30 sites although `core/schema.TARGET_COLUMNS` exists
  (e.g. `model/config.py:36`, `model/builder.py:21`, `workflow/retarget.py:167`, `workflow/reports.py:27`, `cross_asset/model.py:26`,
  `workflow/wiring_selftest.py` x8). The existing guard `tests/test_core_single_source.py` only forbids hard-coded last_candles
  indexes in `cross_asset` (`test_cross_asset_has_no_hard_coded_last_candles_column_index`): the guard was scoped to where the
  bug was found, not to the class.
- **Cost of "add one head type" today (counted):** `model/heads.py` (register), `model/builder.py` (the `nig_regression`
  special case, lines ~207-241), `model/config.py` (head_types), `workflow/run.py` (hard-coded list), `workflow/training_config.py`
  (target dict), `trainer/tasks.py` (loss), `data/heads.py` (`HEAD_KINDS = ('class','reg')`, `split_head_name` raises on a new
  suffix), `data/windows.py`+`data/pipeline.py` (label build), `workflow/batches.py:26` (`== "classification"` label cast),
  `model/diagnostics.py`, `workflow/selective_eval.py`, `evaluation/targets.py`, plus 43 test files that mention head/output names.
  About 12 non-test modules.

**Structural fix.** One tier-0 declaration module `core/heads.py` (pure data, imports nothing): `HeadSpec(name, kind,
output_keys: {role: key}, label_key, task_type, label_encoding, default_weight, eval_role)` plus `output_key(target, role)` /
`parse_output_key(key)` as the ONLY place that knows `y_{t}_...`. Everything else derives from a `HeadSet` built once from
settings: `model.builder` builds heads for a `HeadSet`, `workflow/training_config.build_target_configs` is generated from it,
`data/heads.get_target_heads` becomes a thin view, `evaluation.TargetSpec` and diagnostics query it. Loss weights become a
`LossPlan` section of `RunSettings.train` (static weights, balancing method by registered name, sub-term schedules), validated
in `__post_init__` (see C2); the Kendall exclude-by-type rule becomes a per-head flag in `HeadSpec`. The existing registries
(`HEAD_REGISTRY`, `TASK_REGISTRY`) stay; they gain a declared contract (C8).
Where: `core/heads.py` (tier 0, `check_deps` already enforces "imports nothing"); `RunSettings.train.loss` in
`workflow/settings.py`. Consumers call `core.heads` helpers, never format `y_` names.

**Guard (mandatory).** `tests/test_head_vocabulary_single_source.py`: AST-scan every non-test, non-`core/heads.py` module for
(a) f-strings/constants matching `y_{...}_(class_logits|nu|alpha|beta|confidence|epistemic|aleatoric)` and `.endswith("_class_logits")`,
(b) literal tuples/lists equal to `('high','low','close')`; fail on any not in a frozen per-file count baseline
(`tools/pattern_baseline.json`, may only shrink, same ratchet idea as `implicit_deps_allowlist.txt`). Plus a round-trip test:
`HeadSet` -> model outputs keys == `build_target_configs` output_keys == `TargetSpec` set, for every `RunSettings` variant of
`tests/run_fixture.py`. A second test: `RunSettings.train.loss` with an unknown method/head name raises at construction.

**Byte-identical proof.** Existing: `tests/test_run_steps.py` (pins training config, model structure, batches, chicks decode
specs for 6 variants against `golden_run_settings.json`) and `tests/test_model_trainer_packages.py`. New: a fingerprint of
`build_config(...)["targets"]` and `model.output_names` for each variant generated BEFORE the refactor and asserted equal
after; `trainer.loss_weights` initial values equal; one trained epoch loss equal to the recorded value at rtol 0 on CPU.
Migration is leaf-first: introduce `core/heads.py`, point one consumer at a time (one `refactor` commit each), ratchet down.

**Effort/risk.** L (staged over 3-4 PRs), medium risk (checkpoints depend on layer names `y_{t}_class_logits`; layer names must
not change, only who formats them). Depends on: none (C2 can land first or beside). Unblocks: multi-head experiments, cascaded
stage (a).

### C2. Configuration is accepted, not validated: three config systems, silent defaults, dead keys, a false doc claim

**Flaw.** Config validation exists in pieces (strict in `RunSettings`, partial in `update_config`, absent in `build_config`), so
a typo or a stale key changes the experiment without an error, which is what "no silent defaults" forbids.

**Evidence.**
- **Verified:** `trainer.build_config` (`trainer/config.py:194-221`) accepts every one of: an unknown top-level key (`losss`),
  a typo'd target key (`loss_wieght`), negative / NaN / string `loss_weight`, a typo'd `loss` key
  (`use_uncertainity_weighting`), an unregistered `task_type`, a `lambda_reg_var` naming a schedule that does not exist. The card
  says the opposite (`trainer/config.py:5`, PITFALLS "Unknown config keys raise in build_config"). Failures surface later or
  never: an unregistered task type raises a bare `KeyError` at `GenericTrainer.__init__`; a missing schedule name silently turns
  the regularizer OFF (`trainer/tasks.py:207`, `... else tf.constant(0.0)`, same at :239); a typo'd `loss_weight` becomes 1.0.
- `data/runtime.py:39` `_reject_unknown_keys` checks TOP-LEVEL keys only; nested typos (`abstention.min_margn`) pass.
- 19 of 101 `PIPELINE_DEFAULT_CONFIG` keys are read nowhere (verified by regex over the code packages): `scaling_window,
  kv_latent, expansion, model_dropout, decomp_kernels, moe_every, n_shared, n_routed, gradient_clipnorm, use_class_weights,
  class_weight_smoothing, reduce_lr_patience, reduce_lr_factor, eval_batch_size, eval_range_frac, eval_n_display, workspace_dir,
  use_drive, preprocessed_data_file_id` (+ `target_loss_weights`, see C1). `gradient_clipnorm` and `use_class_weights` look like
  live training knobs; changing them does nothing.
- Default values are restated at the point of use although `TRAINER_DEFAULT_CONFIG` already merges them: `trainer/system.py` has
  25 `.get('k', default)` (e.g. `patience`, `min_delta`, `smoothing_window`, `ema_beta`, `max_to_keep`, `save_every`,
  `mirror_every`), `trainer/tasks.py` 13 (`huber_delta` default 1.0 stated twice, `:214` and `:266`), `data/split.py` 16,
  `data/heads.py` 11. Each is a second default that can drift from the first.
- Inter-stage "contract" is stamped loose keys on split dicts with silent fallbacks: `reg_target_scale`, `reg_target_scales`,
  `target_mode`, `entry_close_reg`, `price_norm_meta` set at `workflow/retarget.py:136-138` and read with
  `.get(key, default)` in 45 places (`workflow/splits.py:33-43` returns 1.0 "if absent").
- Config derived from data sits inside the hashed config: `callbacks.class_baselines` (`workflow/run.py:334`) is computed from
  val and stored in `main_config`, therefore in `config_fingerprint`.
- Config overlaps: pipeline `CONFIG` (101 keys), trainer config (6 sections), `MODEL_CONFIG`, `ANTI_MEMORIZATION_CONFIG`,
  `RunSettings` (7 sections), `PanelSettings`/cross_asset cfg, discovery configs. Only `RunSettings` is a frozen strict object.
  `model.build_model_fn` (`model/config.py:80-87`) merges a dict and relies on Python's `TypeError` for unknown keys.

**Structural fix.** One validation boundary per config surface, built from a declared schema, not hand-written checks:
`core/schema_check.py` (tier 0): `validate(cfg, schema)` where schema = `{key: (type, default, check, doc)}` nested, unknown key =
error with did-you-mean, defaults live ONLY in the schema (the `.get('k', d)` calls become `cfg[k]`). Apply it at the three
entry points that already exist: `trainer.build_config` (targets/loss/optimizer/callbacks/checkpoint/run sections, plus
cross-checks: `task_type` registered, `*_var` names exist in `loss.schedules`, `monitor` is a metric the trainer produces,
`loss_weight` finite and >= 0), `data.update_config`/`load_config` (nested), `model.build_model_fn`. Derived data
(`class_baselines`) moves out of the hashed config. Dead keys are removed in a separate `refactor` PR after a repo-wide grep.
Where: `core/` for the validator, schemas next to each default dict. Consumers: call `validate` at the existing boundaries only.

**Guard (mandatory).** `tests/test_config_strictness.py`: for each config entry point, a parametrized table of mutations
(unknown top key, unknown nested key, wrong type, NaN, unregistered name, dangling reference) that must raise; plus a test that
every key of each `*_DEFAULT_CONFIG` is read somewhere (AST scan for the quoted key outside the defaults file and tests; the
current 19-20 dead keys become the frozen allowlist, may only shrink); plus a ratchet on `.get('<key in DEFAULT>', <literal>)`
counts per file (`tools/pattern_baseline.json`).

**Byte-identical proof.** Validation only rejects; assert that every config produced by the 6 `RunSettings` variants and all
test fixtures passes unchanged and `config_fingerprint` is identical. Removing `.get` defaults: the schema default equals the
old literal, asserted per key by a test that builds the config both ways. Dead-key removal: `golden_run_settings.json` `defaults`
section plus `tests/test_config_collisions.py` still pass.

**Effort/risk.** M-L. Risk low for the validator (rejects only), medium for removing dead keys (old saved configs/notebooks in
Drive may mention them: keep a one-release "deprecated, ignored" list that warns). Depends on: none; C1's `LossPlan` is validated
by it.

### C3. A run has no persisted identity: resume is unchecked, seeds are not a setting, the run folder name is hand-built

**Flaw.** "Which exact experiment produced this checkpoint/result" is not an object, so resume, multi-seed, and result
provenance each approximate it differently.

**Evidence.**
- **Verified (repro `/tmp/probe_resume.py`):** train 2 epochs with `loss_weight=1.0`, rebuild the system with
  `loss_weight=5.0` in the same `run_dir`, `train_mode='auto'`: it resumes at epoch 2 and continues with weight 5.0, no error, no
  warning. The saved best-epoch/patience state (`BestModelTracker.get_state`) comes from the old objective (inferred, not run).
  Cause: `config_fingerprint` (`trainer/config.py:238`) is used only for the in-session `TRAINER_REGISTRY` cache
  (`trainer/system.py:149-157`); it is never written to `meta.json` (`trainer/checkpoints.py:117-124`) and never compared on
  disk resume. `model_signature` is cached the same way (`system.py:292`) and never compared. `restore` only calls
  `assert_existing_objects_matched` (`checkpoints.py:102`), which catches structure, not hyperparameters.
- `cross_asset/train.py:264-290` does persist and compare a fingerprint (`_fp`) and a data fingerprint (`data_fp`): the
  right design exists in one of two trainers, the other lacks it.
- **Verified (repro `/tmp/probe_seed.py`):** a `tf.data` shuffle created before `tf.keras.utils.set_random_seed(42)` is not
  reproducible after it (order differs), one created after is. `workflow/run.py:344-350 make_datasets` builds the training
  dataset with `seed=None` (`workflow/batches.py:30,56`) BEFORE `build_training_system` seeds (`trainer/system.py:189`), so
  `run.seed` does not control batch order. `TrainSettings` has no `seed` field at all (`workflow/settings.py:180-228`); `seed` is
  also in `_FINGERPRINT_IGNORED_RUN_KEYS` (`trainer/config.py:223`). The multi-seed requirement ("beat seed noise, >= 3 seeds")
  has no first-class seed.
- Run identity encoded as a folder-name suffix assembled by string concatenation (`workflow/settings.py:379-399 run_dir_for`):
  includes target mode, scale, architecture, overrides, suspended targets, but not loss weights, label smoothing, lambda
  schedules, optimizer settings or seed; the same folder is silently reused for different objectives (compounds the first bullet).
- No run manifest in the main path: git sha / data fingerprint / settings are written only by `tools/colab_runner.py:265`
  (`write_manifest`) and by hand (`SYNCED_FROM.txt`, `tools/drive_sync.py`). PHILOSOPHY 5.1 requires commit, non-default settings,
  data fingerprint and seed with every result; `trainer/` writes none of them.
- `set_random_seed` hard-coded to `0` in `trainer/system.py:79` (EMA self-test) and `42` fallback at :189, `default_rng(<literal>)`
  scattered in `workflow/capacity.py`, `workflow/diagnostics.py`: seeds are not threaded from one place.

**Structural fix.** `RunIdentity` (frozen dataclass, `workflow/identity.py` or `trainer/identity.py` as a separate module of the
trainer package): `{schema_version, settings_hash (all objective/arch/optimizer/data settings except epochs & verbosity), seed,
data_fingerprint, code_sha, parent_hashes: tuple}`. Written next to every checkpoint (`identity.json`) and stamped on every
output (prediction table, report). `CheckpointManager.restore` compares the identity and raises on mismatch with a field-level
diff (explicit `allow_changes=("epochs",)` for the legitimate cases). `run_dir_for` is derived from the identity hash plus a
readable prefix, so changing anything that changes the objective changes the folder. `seed` becomes `RunSettings.train.seed`,
and ONE `seed_everything(seed)` is called before any dataset/model construction in `workflow/run.py`; the dataset shuffle seed
derives from it. `parent_hashes` gives chained fingerprints for cascaded stages for free.

**Guard (mandatory).** `tests/test_run_identity.py`: (1) resume with each of {loss_weight, label_smoothing, lambda schedule,
lr, architecture override} changed raises; with only `epochs` changed resumes; (2) two builds with equal `RunSettings.train.seed`
produce identical first-3-batch sample indices and identical epoch-1 loss (CPU, `TF_DETERMINISTIC_OPS`), different seeds differ;
(3) AST ratchet: no `default_rng(<int literal>)`/`set_random_seed(<literal>)` outside tests and `core/seeds.py`.

**Byte-identical proof.** The identity file is additive (default `allow` set reproduces today's resume of old run dirs:
missing `identity.json` = warn once and adopt, never raise, so existing checkpoints stay valid: "a new option's default must
reproduce the old behavior"). Seeding change is NOT byte-identical for batch order by design (it fixes nondeterminism): make it
its own `fix` PR with the repro as the test, kept apart from the `refactor` of `run_dir_for` (which must produce the same
folder names for existing settings: assert `run_dir_for` output equal for the 6 fixture variants, new suffix only when a new
setting is non-default).

**Effort/risk.** M. Risk: Drive run folders in use (names unchanged for defaults, so none). Depends on C2 (validated settings to
hash). Unblocks: multi-seed, walk-forward folds, cascaded stage (d).

### C4. The target transform is not a component: encode/decode of `y` is scattered and stamped on data dicts

**Flaw.** CLAUDE.md's "one component, one interface" was applied to input normalization (`Normalizer`) but not to the TARGET
transform (mode, clip, scale, per-target scale, +relative, entry_range), whose state is stamped as loose keys and decoded
inline wherever a price is needed.

**Evidence.**
- Encode: `data/windows.py:370` (`clip(raw) * reg_scale`) and `workflow/retarget.py:96-120` (same clip-then-scale per mode, with
  9 `base == "<mode>"` branches); inline re-encode in `workflow/verification.py:49`.
- Decode: `data/windows.py:405 invert_reg_predictions`, `evaluation/decode.py:96-108` and `evaluation/targets.py:64-82`
  (`reg_scale`/`relative_to_entry` on `TargetSpec`), inline `/ reg_scale_of(...)` in `workflow/reports.py:27,45`,
  `workflow/chicks_bridge.py:41,68-70`, `workflow/verification.py:118-120`, `workflow/selective_eval.py:50`, `workflow/run.py:397`,
  and a separate `robust_scales` in `cross_asset/experiment.py:110`.
- Mode-name branching outside the owner: `== "entry_range"` / `startswith("entry_range")` in `workflow/run.py` (3),
  `workflow/reports.py:25`, `workflow/selective_eval.py` (2), `cross_asset/train.py` (3), `cross_asset/report.py`, `workflow/settings.py`;
  `mode == "scaled"` at `workflow/reports.py:39`. `entry_range_to_prices` is called by both `collect_signals` and
  `cross_asset.export_signals` with the mode inversion repeated around it.
- `docs/architecture_review.md` W5 proposed `TargetModeSpec(name, build_y, invert_to_prices, eval_spec)`; S8 is not done.
- Pending experiments (T5 E-tgt-001 range regression anchored to last close; E-rel-001) will each add a mode and, today, edit
  these ~10 modules.

**Structural fix.** `TargetCodec` registry mirroring `Normalizer`: `fit(train) -> state`, `encode(raw, state) -> y`,
`decode(pred, state, anchors) -> price/return`, `eval_spec(state) -> TargetSpec`; the codec state lives ON the dataset/model
(as the Normalizer's does) and replaces the stamped keys. `retarget_splits`, `collect_signals`, `chicks_bridge`, `reports`,
`verification` and `cross_asset` call `codec.decode`. A new mode = one new class + one registry line (registration checks the
contract, C8). Lives in `data/targets.py` (new module, shared-namespace like its neighbours) with the pure names staying in
`core/schema.py`.

**Guard (mandatory).** `tests/test_target_codec_single_owner.py`: (1) property test per registered mode:
`decode(encode(x)) == x` on synthetic candles incl. +relative; (2) AST ratchet: no `/ reg_scale_of(` or `* reg_scale` and no
`== "<registered mode>"` outside the codec module (baseline file, may only shrink); (3) every mode in `core.schema.TARGET_MODES`
has a codec and vice versa.

**Byte-identical proof.** `tests/test_run_steps.py` covers retarget splits and decode specs for default/relative/entry_range/
magnitude variants; add golden fingerprints of `retarget_splits` output and of `collect_signals` frames per mode BEFORE the
refactor (this is the "new fingerprint needed": the signal frame is not pinned today).

**Effort/risk.** L, medium-high risk (touches every evaluation path; sign convention of `low` with negative `reg_scale`,
`chicks_bridge.py:70`). Depends on C1 (head roles), partially C5 (frame). Do after C1/C2/C3.

### C5. There is no prediction / decision log: two producers, one timestamp, names parsed by consumers

**Flaw.** The artifact that every downstream study and the planned feedback loop depend on has no schema, no time semantics
beyond one column, and is built twice.

**Evidence.**
- `collect_signals` (`workflow/selective_eval.py:~29-88`) and `export_signals` (`cross_asset/train.py:403-440`) are copies; the
  second says so in its docstring ("same columns as collect_signals"), including the mode-inversion block. Columns are
  per-target ad-hoc names (`mu_<t>`, `wst_<t>`, `conf_<t>`, `p_up_<t>`), consumed by name in `workflow/{market_neutral,chicks_bridge,
  verification,run}.py`, `cross_asset/{report,experiment}.py`, `tools/bracket_eval.py` and ~7 research scripts.
- Time semantics: one `timestamp` (the window end, `lc[:, TS_COL]`), `fut_*` columns are realized values. Missing:
  `prediction_made_at`, `label_available_at` (= timestamp + horizon, derivable only from config), `decision_at`, `outcome_at`,
  `horizon`, `run_id`/`identity_hash`/`seed`/`model_id`/`stage`, `schema_version`. The horizon is a config value, not a column, so
  a consumer cannot state label availability from the table alone.
- The writer is a lambda inside `run_reports` (`workflow/run.py:~520`, `to_csv("signals_<split>.csv.gz")`), path in the CWD, no
  manifest.
- `tools/paired_compare.py` works on any frame with a `ts_col`, which is good, but each consumer passes column names by hand.
- No seam for sample weights/regime labels/teacher outputs travelling with samples through the data pipeline:
  `make_shuffled_dataset._gather` casts every array to float32 (`workflow/batches.py:~37-41`), and the diagnostics recorder
  smuggles `__sample_idx__` through the y dict as float32 with a 2^24 limit (`trainer/training_diagnostics.py:28-41`).

**Structural fix.** `PredictionTable` (new `workflow/prediction_table.py`, schema in `core/prediction_schema.py` as pure
constants): tidy/long format `(timestamp, asset, head, kind, value)` or wide with declared column roles generated from the
`HeadSet` (C1), mandatory columns `timestamp, asset, horizon_ns, prediction_made_at, label_available_at, identity_hash, stage,
schema_version`, optional `decision_*`/`outcome_*` columns added by the feedback loop later. One writer
(`write_table(path, df, identity)` writes `*.meta.json` with commit/settings/data fingerprint/seed, per PHILOSOPHY 5.1), one
reader that validates the schema. `collect_signals` and `export_signals` become two small adapters that fill the same builder.
Also the per-sample side-channel: batches carry a declared `aux` dict (weights, regime id, teacher outputs) typed by name, not
smuggled in `y`. This is also the "stage contract" of the cascaded proposal (b).

**Guard (mandatory).** `tests/test_prediction_table_contract.py`: both producers' output passes `validate_table` (columns,
dtypes, `label_available_at >= timestamp`, monotone per asset, schema_version present); a leakage test: shift a future label and
assert no column dated `<= prediction_made_at` changes (extends `tests/test_no_lookahead.py` to the table); ratchet on consumers
reading `df[f"p_up_{...}"]` outside `core/prediction_schema` accessors.

**Byte-identical proof.** The new columns are additive: assert the old columns of `collect_signals`/`export_signals` are equal
(`pd.testing.assert_frame_equal`) on the run fixture for every target mode, before/after. New fingerprint needed: signal-frame
hash per mode (also used by C4).

**Effort/risk.** M. Low risk if additive. Depends on C1 (head roles), C3 (identity), enables C6/cascade/evaluation reuse.

### C6. Leakage control is a config recipe, not a property of samples; the one fold loop in the trainer is a trap

**Flaw.** Purge/embargo are computed from config (window + horizon) at split time; samples do not carry `label_end` /
`available_at`, so every new consumer (new horizon, new stage, folds) must re-derive the rule or skip it.

**Evidence.**
- `data/split.py:52-96` computes the embargo from `window_sizes`, `forecast_horizon`, `timeframes` (good logic, including the
  multi-timeframe span and the phase rule) but a sample's label end is not stored anywhere (grep for `label_end|available_at`
  finds nothing in the code packages).
- `trainer/kfold.py:16-24 purged_walk_forward_splits(n_samples, n_splits, purge=50, embargo=50)`: the `embargo` argument is
  never used; `purge` is a fixed number of sample INDICES (not time), ignores window span, stride, horizon, asset pooling order
  (samples are ordered coin by coin, then time, `workflow/batches.py` docstring), and only the train side is purged. No caller
  exists (`tests/test_model_trainer_packages.py:157` only asserts it is excluded). A researcher reaching for "walk-forward in the
  trainer" gets a leaky splitter by default; the correct one is `data/split.rolling_splits` (line 831), which is not wired to
  any training loop.
- Other splitters: `tools/stale_bars_audit.py:227` (documented as without embargo), `cross_asset/data.py` (`PanelSplit`),
  `workflow/market_neutral.py:36` recomputes `embargo_duration`.
- `split_mode='per_asset'` is documented as leaking (`data/split.py` card) and is still selectable.
- No out-of-fold prediction generator exists (needed for cascaded stage (c), calibration fit on OOF, regime models).

**Structural fix.** (1) Samples carry `label_end` (timestamp of the last bar the label depends on) and `feature_end`; computed
once in `data/windows.py` from the horizon, stored in `last_candles`-adjacent aux (append-only, per `core/schema.py` rule).
(2) ONE `SplitPlan` object (`data/split_plan.py`): train/val/test index sets chosen by time cut, purge = drop train samples with
`label_end > val_start`, embargo = drop val samples with `feature_start < train_cut + gap`; `rolling_splits` and the global split
both produce it; kfold/OOF is `for fold in plan.folds`. (3) `trainer/kfold.py` is either rebuilt on `SplitPlan` or removed
(`move`/delete PR; it has no caller). (4) `oof_predictions(plan, train_fn, predict_fn) -> PredictionTable` (C5) in a new module.

**Guard (mandatory).** `tests/test_split_purity.py`: for every splitter (global_time, per_asset, rolling, panel, any future),
assert `max(train.label_end) < min(val.feature_start)` and likewise val/test, on synthetic multi-asset data with horizon > 1 and a
multi-timeframe config; includes a deliberately leaky splitter that must be caught (as PHILOSOPHY 5 demands for no-lookahead
tests). A registry test: every function whose name matches `*split*` in code packages is covered by the purity test list (AST
scan), so a new splitter cannot bypass it.

**Byte-identical proof.** `split_data` outputs are pinned by `tests/test_data_package.py`, `test_multi_tf.py`
(`golden_pre_multi_tf.json`) and the `run_steps` fixtures: the refactor must keep every split array identical; adding
`label_end` is additive.

**Effort/risk.** M. Medium risk only in the `data/split.py` refactor (the existing logic is the reference; wrap, do not rewrite).
Depends on C5 for OOF tables; independent otherwise.

### C7. Metric definitions have no owner, and the model-selection metric is the training objective

**Flaw.** The same statistic is re-implemented per consumer (so "AUC 0.55" can mean slightly different things), and best-epoch
selection reuses the loss (so changing the loss changes the yardstick).

**Evidence.**
- AUC: `model/diagnostics.py:94`, `workflow/generalization.py:125` (allowlisted duplicate, `tools/implicit_deps_allowlist.txt`),
  research copies; rank-IC: `signal_eval/core.py:18 compute_ic`, `workflow/market_neutral.py:156 _rank_ic`,
  `tools/paired_compare.py:318 _ic_series`, `cross_asset/train.py:80,391 day_pearson/group_ic`, `research/edge_discovery/lib.py:36`;
  Spearman `model/diagnostics.py:102` (and `workflow/capacity.py` borrows it across packages); Wilson interval
  `workflow/selective_eval.py:99` vs `evaluation/targets.py:228`; pinball `tools/natr_range.py:100` vs research. S4 of the earlier
  review (`stats/`) was never done.
- Metrics also live inside loss functions as `stats` (`trainer/tasks.py:225-233`: `mae`, `aleatoric`, ...), so training-time
  `val_*` metrics and report metrics are separate definitions of "MAE".
- Selection = objective: `early_stopping_monitor="val_raw_loss"` (`workflow/settings.py:199`) where `raw_loss` = sum of
  weighted task losses + scheduled penalties + model regularizers (`trainer/trainer.py:153-159`); lambda warm-up changes the
  scale during the first epochs by construction.
- `trainer/ensemble.py`, `evaluation/trust_calibration.py:205` (`_ece_quantile`) and `evaluation/` contain further private metric code.

**Structural fix.** `stats/metrics.py` (tier-1 pure numpy, importable by every code package, never imports data/model/trainer):
one definition each for AUC, rank-IC (per-timestamp, cross-sectional), Pearson/Spearman, Wilson, pinball, ECE, MAE with the
documented tie/NaN policy; consumers import it (and the three allowlisted duplicates disappear from the allowlist). A
`SelectionMetric` is a trainer-side registered validation metric computed from outputs/labels on val with FIXED definition
(e.g. val AUC of head X, val pinball), independent of `loss_weights`; `early_stopping.monitor` names a registered metric, and
unknown names raise at `build_config` (C2).

**Guard (mandatory).** `tests/test_metrics_single_owner.py`: AST scan for top-level or nested definitions whose names match the
metric names (`auc|roc_auc|rank_ic|spearman|wilson|pinball|ece`) outside `stats/` (frozen baseline, only shrinks), plus numeric
cross-checks of `stats.auc` against `sklearn.metrics.roc_auc_score` with ties and NaN. A trainer test: changing `loss_weight`
must not change `val_<selection metric>` for fixed model outputs.

**Byte-identical proof.** For each consumer, call old and new implementation on the same random + tie-heavy arrays and assert
bit-equal (`rtol=0`) BEFORE switching it; where the old copies differ, record the difference in the PR (that is a finding, not a
regression) and keep the old behaviour behind the consumer until the owner decides.
Selection-metric change is a behaviour change: separate `feat` PR with the old `val_raw_loss` as the default (default reproduces
old behaviour).

**Effort/risk.** M (stats consolidation), S-M (selection metric). Risk low for stats, medium for selection (changes best-epoch
choice only when opted in). Depends on C2 for monitor validation. Enables C5 per-stage scoring.

### C8. Registries have no shared contract primitive; guards are written per instance and mostly look backward

**Flaw.** Five pluggable concepts (`TASK_REGISTRY`, `HEAD_REGISTRY`, `NORMALIZERS`, `SAMPLE_FILTER_REGISTRY`, signal_eval
hypothesis registry) each implement registration differently, with no declared contract checked at registration; and structural
guards (`test_core_single_source`, the card ratchet, `implicit_deps`) each fence one past incident.

**Evidence.**
- `register_task_type` (`trainer/tasks.py:71-77`) and `register_head_type` (`model/heads.py:26-30`) overwrite a name silently, accept
  any callable, validate nothing (no output-key contract for a head, no check that `stat_keys` equal the keys the loss returns:
  a mismatch surfaces at training-step trace time, `trainer/trainer.py:150`). `NORMALIZERS` is a hard-coded tuple of instances
  in the registry file (`data/normalizers.py:424`), so adding one means editing it (the others use decorators/functions);
  `signal_eval` registry replaces an existing id entirely (card PITFALLS). The sample-filter registry checks callability only.
- `TASK_REGISTRY[...]` direct indexing in `GenericTrainer._create_metrics` (`trainer/trainer.py:84`) gives a bare `KeyError`
  for an unknown type, in contrast to `build_head_output`'s clear message.
- A loss function's declared contract (`supports_sample_weight`) is checked only when a weight actually arrives
  (`trainer/trainer.py:119-124`), i.e. possibly hours into training for curriculum/weighting runs; the owner's lens
  ("contract checks fail at registration, not hours into training") is not met anywhere.
- Guards are scoped to the incident: hard-coded-index guard only for `cross_asset` (see C1); `implicit_deps` covers name
  resolution, not behaviour duplication; no ratchet exists on `.get(k, default)`, output-name literals, mode-name branches, seed
  literals, or metric re-definitions (the five patterns found in C1-C7).

**Structural fix.** `core/registry.py` (tier 0, pure python, no TF): `Registry(kind, contract)` with `register(name, obj, **meta)`
that raises on duplicate names, runs `contract.check(obj, meta)` immediately (for losses: call the function on tiny synthetic
tensors via an injectable `probe`, check returned stat keys equal `stat_keys`, check `sample_weight` support by a weighted call),
exposes `names()` and `get(name)` with a did-you-mean error. Existing registries become instances (mechanical `refactor`,
dictionaries stay accessible under the old names for notebooks and tests). Contracts: `TaskSpec(name, version, fn, stat_keys,
supports_sample_weight, requires_roles)`, `HeadTypeSpec(name, outputs: roles, label_kind)`, `CodecSpec`, `NormalizerSpec`.
Auto-discovery is NOT proposed (see lens section).

**Guard (mandatory).** `tests/test_registry_contracts.py`: every registered object of every registry passes `contract.check`
(import all modules that register, iterate `names()`); duplicate registration raises; plus the new
`tools/check_patterns.py` ratchet (the generic version of the per-class AST guards named in C1-C7, one script, one baseline
file `tools/pattern_baseline.json`, counts per file may only shrink, `--prune` like `implicit_deps`, wired into
`tools/check_deps.py`/CI `structure` job and the pre-commit hook).

**Byte-identical proof.** Registry contents (names, stat_keys, flags) fingerprinted before/after; all `tests/test_*packages.py`
pass; no computation changes.

**Effort/risk.** S-M. Low risk. Depends on none; should land FIRST because C1/C4/C7 register through it and the ratchet tool
carries the other classes' guards.
